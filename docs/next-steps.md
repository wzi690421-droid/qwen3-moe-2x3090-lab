## 下一条值得讨论的实验

目标是改善小 batch 的专家 GEMM。先读对应版本的 Python 参数入口和 C++ launch selector，确定自动配置实际选择，再提出一个 tile / blocks-per-SM 候选。

每个候选记录：

1. 对应函数、形状和可证伪的预测。
2. 固定权重、输入、路由下的默认 A → 候选 B → 默认 A。
3. 延迟分布、FP32 参照误差、重复性和停止原因。
4. 若有稳定收益，再覆盖多个 M、seed、路由和 W2。
5. 最后确认整机执行到了候选路径，重新检查质量和固定负载性能。

只有这些证据支持收益，才考虑把 selector 改动或基准工具贡献到上游。贡献前还要在目标 commit 上复验并检索已有 issue / PR；本轮没有 merge 保证。

## 学习练习

- 自己用小维度 CPU 写 router → top-k → 专家 FFN → 加权 combine。
- 画出 TP 与 EP 的矩阵形状，解释当前 W13 的 M=8、N=768、K=2048。
- 从一条原始 JSON 复算吞吐，说明 TTFT、TPOT 和计时边界。
- 从 GPU decode 区间解释每步 97 次 AllReduce 的入口。
- 逐行区分探针的数据构造、权重准备、数值参照和计时。

## 恢复环境前

核对模型 revision、包版本和卡间 P2P；另一台双 3090 的通信路径可能不同。模型权重及 venv 需自己保留或重新准备，本仓库只提供实验材料。新 GPU 实验由你操作，我们讨论后再运行。
